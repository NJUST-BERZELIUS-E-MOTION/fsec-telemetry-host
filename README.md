# SerialJsonHost —— LoRa 遥测上位机

解析并显示嵌入式板卡(STM32 LoRa 测试板)通过**串口**输出的 **JSON 格式**数据的
Qt6 上位机。C++17 / Qt 6.11.1 (Widgets + SerialPort) / CMake / VSCode 开发。

配套固件位于仓库内的 `单片机代码/Lora/Lora测试板`
(USART1, **115200, 8 数据位 / 无校验 / 1 停止位**)。

## 一、功能(当前: 接收 + 自适应显示 + 字段选择 + 结构化样本保存)

| 页签/控件 | 说明 |
| --- | --- |
| 原始数据 | 串口收到的每一行原样显示(JSON 绿色 / 设备日志白 / 系统消息蓝色), 支持时间戳、暂停刷新、清空 |
| 遥测数据 | **根据接收内容自适应**：一行 JSON → 拆成 0..N 条样本(burst 合包逐帧拆开)；字段首次出现自动注册显示；最新值表 + 最近 500 条样本记录 + 样本/包/速率统计 |
| 字段选择(面板) | 遥测页左侧按域分组列出全部字段(包信息/高压/低压/踏板/运动/TC/状态/LoRa/动态字段)，勾选决定显示哪些；全选/全不选、双击分组整组开关；选择记忆到下次启动 |
| 文件记录(记录栏) | 手动"开始/停止记录"；**一次记录 = 一个文件夹**：`<文件夹>/burst.jsonl`(周期合包, 已拆帧)、`data.jsonl`、`event.jsonl`、`other.jsonl`，停止时同目录写 `meta.json`(会话信息/字段定义/各类计数)；每行一条样本且**键顺序固定**(seq,line_seq,host_time,type,config_id,ts,rssi,再按字段表顺序)；"导出可读JSON"生成 `<文件夹>/<类型>.pretty.json` |
| 导入查看 | "导入查看…"可多选记录文件夹里的 `burst/data/event/other.jsonl`、`*.pretty.json`、`meta.json`，用同一套记录表/最新值/LED/曲线回看；可选清空后导入或追加；导入不写回任何文件 |
| 导出VBO | "导出VBO…"把本次记录会话的全部样本写成 **VBOX 文本格式(.vbo)**: `File created on…` + `[header]` + `[channel units]` + `[comments]` + `[column names]` + `[data]`；通道=字段表中出现过的数值字段(布尔按0/1)，时间基为设备ts去回卷后相对首样本(秒)，按时间排序，缺值填0；用于 GSpot/VBOX 类工具查看 |
| 异常检测/留证 | `fields.json` 每个字段可配 `min`/`max` 合理范围：越界值在最新值/记录表**标红**；曲线中**坏点直接不显示并断开连线**(不跨坏点插值，也避免单个异常点拉爆纵轴)，统计栏"异常"计数；越界样本与解析失败的原始 JSON 行自动留证到 `recordings/anomalies/anomaly_日期.jsonl` |
| 状态LED(右侧) | 遥测页右侧常驻"状态/标志指示"：布尔字段(在线/闭合/按下等)显示为 LED 圆点——绿=在线/有效, 红=掉线/无效, 灰=暂无数据, 不受字段勾选影响 |
| 曲线 | 纵轴=数据字段(勾选可多画), 横轴可选 **样本序号 / 设备时间ts(ms) / 主机时间(相对秒)**；布局可选 **同图叠加 / 分图(每字段一张, 各自量程)**；同图可选纵轴**共用/每条独立**；处理模式 **原始 / 一阶低通(τ 手动可调, ms)**；越界/缺失样本处曲线**断开显示**(不插值)；**显示范围过滤**可在看图时直接设 min/max，范围外样本不画；可设每线点数上限并手动清空；左键框选放大、"重置缩放"恢复；悬停点显示数值(低通时附原始值) |

串口控制条: 端口下拉 + 刷新、波特率(默认 115200)、打开/关闭、暂停刷新; 记住上次使用的端口/波特率。

> 已预留"数据其它处理方式"的接口(`ISink`, 见下), 已挂三个出口:
> 原始日志显示、遥测样本表格显示、结构化样本文件记录; 曲线/统计/转发等后续只需实现 `ISink` 并注册, **不用改流水线**。

## 二、固件端输出形态(为什么这样设计)

测试板把**两类内容**混在同一根串口上输出:

1. **JSON 遥测行**(收到 LoRa 数据时 printf, 单对象一行, `\r\n` 结尾)。按固件 `config_id` 有三种形态:
   - `burst` 周期合包(`config_id=10`): 一行含 `frames` 数组(一次 4 帧), 由上位机逐帧拆开;
   - `event` 事件流(`config_id=20`): 一行=一条, `vehicle_flags` 展开成 8 个状态布尔;
   - `data` 默认单帧: 一行=一条, 字段随所选配置(通道表)变化;
2. **文本日志**(Log_Write, `\n` 结尾): `RX DONE`、`SPI Check Success` 等。

因此上位机数据流为:
```
串口字节流 → 按行切分(兼容 \r\n 与 \n)
          → 每行尝试解析 JSON
              ├─ 失败 → 设备日志(仅"原始数据"页)
              └─ 成功 → 拆帧解码 0..N 条样本(record)
                        → 界面/文件记录按样本呈现, 字段集合随内容自适应
```

## 五、构建与运行

### 方式 A: VSCode(推荐)
1. 用 VSCode 打开本文件夹 `上位机`;
2. 按提示安装推荐扩展(C/C++、CMake Tools);
3. 构建: `Ctrl+Shift+B`(默认任务 = MSVC Debug);
4. 调试运行: `F5` —— 选 "Debug (MSVC 2022)" 或 "Debug (MinGW 13.1)"
   (会自动先执行对应构建任务, 并注入 Qt DLL 路径)。

> MSVC 配置只需首次执行; 之后改代码直接 F5 即可。

### 方式 B: 命令行(PowerShell)
```powershell
# 默认 MSVC Debug 构建
.\scripts\build.ps1

# 其它组合
.\scripts\build.ps1 -Toolchain msvc  -Config Release
.\scripts\build.ps1 -Toolchain mingw -Config Debug
.\scripts\build.ps1 -Toolchain msvc  -Config Debug -Run      # 构建并运行
.\scripts\build.ps1 -Toolchain msvc  -Config Release -Deploy # 构建并把 Qt DLL 部署到 exe 旁
```

生成物: `build/msvc/<Debug|Release>/SerialJsonHost.exe`(MSVC)
或 `build/mingw/SerialJsonHost.exe`(MinGW)。`config/fields.json` 会在构建时
自动复制到 exe 同级目录。

### 运行注意
- 从 VSCode 调试或 `-Run` 运行时脚本已把 Qt `bin` 加入 PATH, 可直接运行;
- 若要脱离开发环境双击运行 exe, 请先执行一次 `-Deploy`(把 Qt 运行库部署到 exe 旁)。

## 六、使用步骤

1. 给板子供电并接好 USB 串口, 确认设备管理器里出现 COM 口;
2. 本程序点"刷新"选中该 COM 口(波特率默认 115200);
3. 点"打开串口" —— 原始数据页立即出现板卡输出的每一行;
4. 收到 JSON 遥测后, "遥测数据"页自动按内容展开: burst 逐帧成行、未知字段自动出现;
   左侧"显示字段"面板可勾选只看想看的字段(选择会被记住);
5. **保存记录(可选)**:
   - 点"记录文件夹…"选择/输入**文件夹名**(程序自动创建该文件夹); 文件夹内按帧类型写:
     `burst.jsonl`(周期合包, 已拆帧)、`data.jsonl`、`event.jsonl`、`other.jsonl`;
   - 或不做任何选择直接点"开始记录" —— 默认文件夹 `exe同级/recordings/SerialJsonHost_时间戳/`;
   - 每行一条样本, 键顺序固定(seq,line_seq,host_time,type,config_id,ts,rssi,再按字段表顺序), 便于顺读;
   - 点"停止记录": 关闭文件并写 `<文件夹>/meta.json`(端口/波特率/起止时间/各类计数/字段定义);
   - 需要给人看时点 **"导出可读JSON"** —— 生成 `<文件夹>/<类型>.pretty.json`;
   - 点 **"导出VBO…"** —— 生成 VBOX 文本 `<文件夹>/export.vbo`;
   - 注意: 同名文件夹已存在时**追加**写入(要干净结果请换新文件夹名);
   - 记录不因界面"暂停刷新"而中断; 关串口/关程序前记得点"停止记录"(才会写 meta.json)。
6. **导入历史记录回看(可选)**:
   - 点 **"导入查看…"**, 可**多选**记录文件夹里的 `burst/data/event/other.jsonl`、
     `*.pretty.json`、`meta.json`(meta 只显示会话摘要, 不算样本);
   - 已有数据时会询问: **是=清空后导入**(推荐，看某一次记录) / **否=追加** / 取消;
   - 导入后"遥测数据"页(记录表、最新值、右侧 LED)与"曲线"页都用当前字段勾选、
     X 轴、布局、滤波设置重新呈现;**导入只用于查看, 绝不会写入记录文件**;
   - 说明: 记录表/曲线仍按"最近 N 条(记录表500 / 曲线点数上限)"显示, 超大文件只看尾部;
     文件里的 `seq/line_seq/host_time` 会被恢复成样本序号/行号/时间。
7. 联调验证:
   - 固件端 `Log_Read()` 输出的调试日志 → 应出现在**原始数据**页;
   - 两块 LoRa 板互发, 接收板打印的 JSON → 原始数据页绿色行 + 遥测页按样本刷新; 记录中时文件里同步新增样本行。

## 七、修改显示字段

编辑 `config/fields.json`(`key` 必须与固件输出 JSON 的键一致), 如:

```json
{ "key": "voltage", "label": "电池电压", "unit": "V", "decimals": 2, "min": 0, "max": 600 }
```

- `min`/`max`(可选)是**合理范围**: 两者都配置才启用; 越界值在表格标红、
  曲线里被剔除(防止一个异常点把纵轴拉爆), 并计入"异常"计数与留证文件;
- 范围只是启发式, 按你车的实际量程调整即可; 不想校验就删掉这两个键;
- 改完重新构建即可(文件随构建拷贝)。字段缺省时程序内置了默认表(无范围校验)。
- **不想改配置、只想临时屏蔽某字段的超范围值**: 打开**曲线页 → "显示范围(看时可改)"**,
  选字段、填最小/最大、点"应用到该字段"(或"清除该字段")即可立即重画;
  范围外样本不画、曲线在该处断开、纵轴不被拉高。该过滤**只影响曲线显示**,
  不改 `fields.json`, 也不影响记录表标红/异常统计; 设了范围的字段以你输入的范围为准。

## 八、异常数据排查建议

若发现"偶发很大的数": 先看**原始数据页**那一行——如果原始 JSON 里就是大数,
说明问题在固件/无线侧(常见: 收发两端固件通道表/类型/帧长不一致 → 逐帧错位;
U16/S16 读到 0xFFFF/0x8000 再乘 scale)。上位机的范围校验/留证可帮你快速抓样本:
`recordings/anomalies/anomaly_日期.jsonl` 里存着原始行与越界字段说明。

## 十、常见问题

| 现象 | 处理 |
| --- | --- |
| 列表里没有 COM 口 | 检查 USB-TTL 驱动(CH340 等); 点"刷新"; 若被串口助手占用会打不开 |
| 点"打开串口"提示被占用 | 关闭其它串口工具(串口助手、另一实例) |
| 能收到文本但"遥测数据"不刷新 | 板子当前只发了日志没发遥测; 或 JSON 键不是 `type:"data"`(先看原始数据页内容) |
| 中文乱码 | 固件侧 ASCII 为主; 本工程源码/配置文件一律 UTF-8, 勿用 GBK 编辑器另存 |
| 拔线后程序报"端口异常断开" | 正常提示; 程序自动回到未连接状态, 插回后重新打开即可 |
